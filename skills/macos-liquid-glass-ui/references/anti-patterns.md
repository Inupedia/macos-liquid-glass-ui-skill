# Anti-patterns：Liquid Glass 常见失败模式

本文件用于审查和生成时做负向约束。Agent 看到这些模式时应主动修正，而不是把它们当成“风格选择”。

## A. 材质失败

### A1. 全页玻璃化

**现象**：背景、正文卡片、图表、表格、按钮全部 backdrop blur。

**问题**：失去功能层与内容层区别，信息层级混乱，性能差。

**修正**：正文退回 solid surface，只保留导航、控制和临时浮层玻璃。

### A2. Glass on glass

**现象**：玻璃卡片里套玻璃卡片，再套玻璃按钮。

**问题**：边界发灰、层级不可预测、视觉噪声高。

**修正**：一个共享 glass container + 内部普通控件；只在语义需要时拆层。

### A3. 糖果/果冻材质

**现象**：强高光、厚透明、彩色折射、软塑料感。

**问题**：更像 3D toy / gummy UI，不像克制的生产工具。

**修正**：减弱 refraction、glow、specular；提高主体轮廓与内容稳定性。

### A4. 为了展示玻璃制造无意义背景

**现象**：页面角落放彩色 gradient blob、发光球，只为了让 blur 可见。

**问题**：装饰凌驾于产品内容。

**修正**：若没有有意义背景，直接使用稳定 surface。

## B. 结构失败

### B1. 所有产品都三栏

**现象**：Sidebar + Main + Inspector 被机械套到文档、简单表单、登录页。

**修正**：先选 page archetype。没有对象属性就不要 Inspector。

### B2. 滚动套滚动

**现象**：页面滚动 > card 滚动 > table/body 再滚动。

**问题**：滚轮和触控行为不可预测，焦点易丢。

**修正**：一个连续阅读任务只保留一个主要纵向滚动主体。

### B3. Sticky 被误当 fixed layout

**现象**：底部按钮用 sticky，却没有明确滚动祖先；内容短时按钮悬在中间。

**修正**：工作台使用 grid/flex 的稳定底行；自然内容页再按需要 sticky。

### B4. 窄屏只缩小

**现象**：三栏、toolbar、表格一起按比例缩小。

**修正**：结构降级：收 sidebar、overlay inspector、toolbar overflow、table 横滚。

## C. macOS 伪装失败

### C1. 假红黄绿窗口按钮

**现象**：Web 页面放三个不能真正控制系统窗口的圆点。

**问题**：伪装 OS chrome，无功能。

**修正**：除非用户明确做 mockup/demo，否则不添加。

### C2. Dock 装饰

**现象**：页面底部加假的 Dock 来制造 Mac 感。

**修正**：删除。平台感来自信息架构、字体、控件、材质和交互。

### C3. 每个按钮都是 capsule

**现象**：普通按钮、icon button、tag、input 全是 999px 圆角。

**修正**：按组件尺寸和容器 concentric 关系使用 6–28px 等不同半径；胶囊只用于适合的控件。

### C4. 把 SF Symbols 风格当装饰插画

**现象**：大量同质小线框图标充当背景装饰。

**修正**：系统符号用于功能识别，装饰要少且有业务意义。

## D. Toolbar / Navigation 失败

### D1. Toolbar button soup

**现象**：十几个同等级按钮并排。

**修正**：按 leading / center / trailing 和 1–3 组重新组织，低频项放 menu/overflow。

### D2. 所有操作塞进 `...`

**现象**：界面“干净”，但高频动作全隐藏。

**修正**：最高频、最高价值动作直接可见。

### D3. 导航体系叠加

**现象**：top nav + sidebar + tabs + breadcrumb + segmented control 同时表达同一层级。

**修正**：每一级信息架构选一种主导航。

### D4. 搜索范围不清

**现象**：Sidebar 和 Toolbar 各有一个 Search，用户不知道搜什么。

**修正**：只保留必要入口并明确 scope / placeholder / section。

## E. 组件失败

### E1. Icon-only everything

**现象**：所有按钮都只有图标，为了“像 Mac”。

**修正**：只有熟悉、高频、上下文清楚的命令适合 icon-only；关键/陌生操作用文字。

### E2. Disabled 无解释

**现象**：按钮灰掉但不知道为什么。

**修正**：条件可推断则保持简洁；不可推断时提供附近解释、tooltip 或状态说明。

### E3. Toast 承担关键错误

**现象**：保存失败只出现 2 秒 toast。

**修正**：关键错误就地保留，提供重试/修复路径。

### E4. Loading 清空旧内容

**现象**：每次刷新整个区域变 skeleton。

**修正**：后台刷新保留旧结果，局部显示 refreshing 状态。

### E5. 假进度

**现象**：未知时长任务从 0% 自动走到 95%。

**修正**：没有可靠总量就使用 indeterminate / step status / event log。

## F. 表单失败

### F1. Placeholder 代替 label

**问题**：输入后字段含义消失，可访问性差。

**修正**：稳定 label；placeholder 只给示例。

### F2. 提交失败清空输入

**修正**：保留输入，定位错误，允许继续编辑。

### F3. 每个字段做两列

**现象**：为了“桌面感”把所有字段横向并排。

**修正**：默认单列；只有强相关短字段并排。

### F4. 简单表单强行 Wizard

**修正**：步骤只有在业务存在真实阶段、依赖或认知分组时使用。

## G. 表格与数据失败

### G1. 管理后台卡片化

**现象**：几十行结构化数据被拆成几十张大卡片。

**修正**：任务需要比较/扫描时保留 table/list。

### G2. 关键字段省略号

**现象**：金额、错误原因、处理状态被 `...` 隐藏。

**修正**：关键值完整或有明确详情路径；操作列保持独立。

### G3. 图表颜色过多

**现象**：每条线一个鲜艳色，再叠透明面积。

**修正**：主系列突出，辅助系列降级；颜色有语义且跨刷新稳定。

### G4. 图表藏在玻璃后

**现象**：canvas 本身透明，背景影响数据读取。

**修正**：图表使用稳定 surface；tooltip/控制层可玻璃化。

## H. 动效失败

### H1. 持续漂浮/呼吸

**修正**：删除非必要循环动画。

### H2. 所有 hover 都 scale

**问题**：桌面工具出现玩具感和布局抖动。

**修正**：hover 主要用背景/边界/轻阴影，scale 只用于少量强调对象。

### H3. 大面积 backdrop-filter 动画

**修正**：避免 blur 连续变化；使用 opacity/transform 等成本更低的反馈。

## I. Accessibility 失败

### I1. 去掉 focus outline

**修正**：提供清晰 `focus-visible`。

### I2. 只用颜色表示状态

**修正**：增加文字、图标、形状或线型。

### I3. Reduce Transparency 后 UI 消失

**修正**：glass 必须有 solid fallback。

### I4. 200% 仍强制三栏

**修正**：允许重排和单栏。

## J. Agent 行为失败

### J1. 不读现有项目就替换设计系统

**修正**：先检查 token、组件库、路由、样式约束和未提交修改。

### J2. 用户只让改局部却全站重构

**修正**：尊重修改范围，复用已批准区域。

### J3. 构建通过就宣称视觉完成

**修正**：报告真实浏览器/尺寸/键盘/状态验证范围。

### J4. 把 Apple 指南中的动态行为硬编码成 Web 像素

**修正**：区分官方语义与本项目 Web baseline，不把近似值说成官方固定参数。

### J5. 为了“完整”编造不存在的状态和数据

**修正**：只覆盖业务确实可能出现的状态；模拟数据明确标注。

## 审查输出格式建议

发现 anti-pattern 时按以下结构写：

```text
问题：A1 全页玻璃化
触发位置：结果区 6 张卡片 + 图表容器
风险：内容层和控制层混合、滚动性能下降
建议：卡片和图表退回 surface，仅 toolbar/filter 保留 glass-regular
验证：浅/深色、Reduce Transparency、滚动性能
```

不要只写“看起来不高级”“不像 macOS”这类不可执行评价。
