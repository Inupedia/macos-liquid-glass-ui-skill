# macOS Liquid Glass UI

跨业务、跨前端框架复用的产品 UI 规范。数值是 Web 设计基线，不是 Apple 官方固定参数；玻璃为 Web 视觉近似。用户指定品牌、已批准样式及修改范围优先。

## 交付范围

- 规范/提示词：输出独立完整规范，包含具体颜色与布局行为，不自动修改项目。
- 设计/实现：检查实际入口、技术栈、现有组件、样式及未提交修改，复用既有能力，不强制换框架或组件库。
- 审查：提供问题、触发条件、建议和验证方式；审查不自动授权实施。
- 跨项目时移除水文、Archify 等业务依赖，不把单页或三栏变成所有产品的要求。

简短声明页面类型、使用人群、目标设备及布局模式；可从上下文判断时直接继续。

## 核心约束

1. 页面/面板级主操作置于所属容器稳定底部，正文展开不能把按钮顶走。筛选、搜索、行内编辑、展开、关闭等局部操作留在对象旁。
2. 明确每个区域的高度来源、伸缩和滚动归属。锁高工作台与自然内容页使用不同骨架。
3. 玻璃用于导航和控制层；正文、图表、表格保持稳定底色。
4. 短屏、放大文字、软键盘优先保证操作和内容可达，不通过裁切或整页缩放维持一屏。
5. 滚动条遵循系统与浏览器偏好，不全局隐藏，不按操作系统强制覆盖用户选择。
6. 加载、空态、错误、结果沿用稳定框架；美化不改变数据含义或编造完成进度。

## 工作方式

先定义简短布局合同：各区域固定/弹性角色、滚动主体、按钮归属、窄屏与短屏降级。随后应用视觉和状态规范。

完整规范须包含色值、尺寸、材质、布局合同、滚动条、溢出、固定操作、组件状态及验收，不只给审美形容词。

实现后验证相关行为，尤其是长内容展开后的按钮位置、窗口高度变化、容器变化后的图表尺寸。使用环境允许的浏览器工具；不依赖特定插件。

交付报告实际完成和验证范围。构建通过不等于视觉验收。不自行发布、改变系统偏好或声称完成未执行的检查。
