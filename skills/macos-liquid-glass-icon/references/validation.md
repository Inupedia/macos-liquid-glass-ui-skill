# Liquid Glass Icon 验收清单

生成完成不等于设计通过。至少做以下检查。本文中的数值阈值是本项目自定基线，不是 Apple 官方数值。

## 1. 语义

- [ ] 不看产品名时，主对象仍能被描述出来。
- [ ] 主隐喻和产品核心用途有关，而不是通用“AI 星星 / 机器人 / 魔法棒”。
- [ ] 没有同时塞入多个互相竞争的概念。
- [ ] 如果基于现有品牌改造，历史识别元素仍然保留。

## 2. 小尺寸可读性

先做真实缩放，再看图判断（不要只在缩放预览里“想象”）。从 1024×1024 成稿生成检查图：

```bash
mkdir -p /tmp/icon-qa
sips -Z 256 final-icon-1024.png --out /tmp/icon-qa/icon-256.png
sips -Z 64  final-icon-1024.png --out /tmp/icon-qa/icon-64.png
sips -Z 32  final-icon-1024.png --out /tmp/icon-qa/icon-32.png
sips -Z 16  final-icon-1024.png --out /tmp/icon-qa/icon-16.png
```

然后逐项确认：

- [ ] 1024 px：材质边缘干净，没有脏点、错误反射或局部畸变。
- [ ] 256 px：层级和主体清晰，不像普通插画。
- [ ] 64 px：主轮廓仍然稳定，辅助元素没有糊成噪声。
- [ ] 32 px：能识别主轮廓和核心色块。
- [ ] 16 px：**主轮廓仍然成立**——能说出“是什么形状 / 什么朝向”即可，不要求辨认细节；若 16 px 只剩一团色斑，回到 1024 删细节或放大主对象占比，不要用锐化补救。

macOS 资产目录的实际尺寸梯度（16pt 等）以 Xcode asset catalog 和 Apple Design Resources 模板为准。

⚠️ **未确证**：本次未取得 HIG 中 macOS 资产目录尺寸梯度表的官方数值，**不要凭记忆写死 px 清单**，以现场模板和 Xcode 为准。

如果必须放大才能理解，优先删细节，不要继续加锐化或高光。

## 3. 可判定基线（本项目自定，不是 Apple 官方数值）

把“好不好”变成“过没过”，评审时给结论而不是形容词。以下数值全部是**本项目自定基线**，不得引用为 Apple 官方规格：

- **主对象最小笔画宽度**：在 1024×1024 原始画布上，主对象任意承重笔画宽度与关键负空间（间隙 / 开孔）≥ **16 px**（约画布宽的 1.5%）；次级元素 ≥ **8 px**。低于此值视为不通过（16 px 缩放后必然消失）。
- **主体与背景对比下限**：主体与其紧邻背景区域的对比度 ≥ **3:1**（在 sRGB 下按 WCAG 相对亮度公式计算）；default 和 dark 两种外观都要满足；clear / tinted 下若系统材质主导，退化为“主体形状边界仍可辨”（在 16 px 检查图上判断）。
- **允许色差容差**：定稿相对冻结 palette 的色差 **ΔE00 ≤ 3**；同一 icon family 内同类元素之间 ≤ 3；高光 / 透明区域局部可放宽到 ≤ 5，但主体识别色不允许偏移。
- **细节预算（QA 判据）**：直接采用 [图标设计系统](icon-system.md) 的 Detail Budget——主对象 **1** / 次级结构 **1–2** / accent **0–2** / 纹理 **0** / 文字 **0**（字母字标本身即品牌时除外）。超出即不通过，先删细节再谈材质。
- **层级预算**：逻辑层 ≤ **4**，且能从后到前命名（对应 Icon Composer 的 4 个 group 上限）。

量测方式：缩放用 `sips -Z`；取色与对比度用取色器或像素读取；色差用 Lab 值算 ΔE00，不要目视估。

## 4. Liquid Glass 材质

- [ ] 玻璃感服务于主体，不会让主体消失。
- [ ] 高光面积克制，没有形成大块白斑。
- [ ] 折射不会制造类似错误文字或杂乱纹理。
- [ ] 没有明显 chrome、镜面金属、果冻糖、塑料气囊感。
- [ ] 前后层关系明确，不靠无限叠加透明层制造复杂度。
- [ ] 背景层没有材质 / 光泽 / 纹理（只允许纯色或渐变）。

## 5. 构图

- [ ] 主体居中且有安全留白。
- [ ] 没有设备 mockup、Dock、桌面场景或展示卡片混入最终图标。
- [ ] 没有文字、乱码、水印或伪品牌名。
- [ ] 没有过细的线、过小的洞或容易被圆角裁切的边缘主体。
- [ ] 图标看起来是 App Icon，而不是海报、产品摄影或完整 UI 截图。

## 6. 品牌与颜色

- [ ] 使用冻结的 HEX palette，没有明显跑色（容差见 §3）。
- [ ] 品牌主色仍占主导，而不是被生成模型替换成默认蓝紫渐变。
- [ ] 深浅背景下主体边缘仍有足够区分度。
- [ ] 同一 icon family 的材质、色温、视角、细节密度一致。
- [ ] 交付已写明色彩空间为 sRGB / Gray Gamma 2.2 / Display P3 之一。

## 7. AI 图像常见错误

重点检查：

- [ ] 伪文字或类似字母的随机符号；
- [ ] 不对称但本应对称的结构；
- [ ] 错误透视、断裂边缘、悬空碎片；
- [ ] 多余按钮、开孔、把手、齿轮或无意义装饰；
- [ ] 边缘出现被裁断的残留元素；
- [ ] 同一材质在左右两侧表现完全不一致。

出现这些问题时优先使用图像编辑局部修正；如果核心结构已经错误，再重新生成。

## 8. 外观变体验收

6 种外观逐项过，不允许只验 default。Icon Composer 的主外观选择器只有 **default / dark / mono**；clear 与 tinted 要在 **Mono → Options**（Light/Dark 切换 + Tinted 开关 + tint 色）里检查。

- [ ] **default**：基线外观，色板、层级、材质关系都成立。
- [ ] **dark**：metaphor 与轮廓不变；背景色场压暗后主体对比仍 ≥ 3:1。
- [ ] **clear light**：形状与轮廓可读，不依赖固有色。
- [ ] **clear dark**：深色环境下轮廓不糊、不被背景吞掉。
- [ ] **tinted light**：单色化后仍靠明度层级区分主次。
- [ ] **tinted dark**：tint 之后主体与背景对比足够。

6 种外观必须保持**同一 metaphor / 轮廓 / 特征**；若某项必须换主体才能通过，视为设计不成立，回到概念层重做。

## 9. Icon Composer 生产检查

如果图标要进入真实 Apple App 项目：

- [ ] 已提供清晰的 2–4 层 layer map，图层命名从后到前且有意义（如 `01-background` / `02-shape` / `03-symbol`）。
- [ ] 图层数 ≤ 4（Icon Composer 的 group 上限）。
- [ ] 生产源图没有预先烘焙平台圆角遮罩。
- [ ] 镜面、高光、折射、模糊、透明度和层间阴影可以在 Icon Composer 中重新控制（源层没有烘焙这些效果）。
- [ ] 导出前已移除背景色与渐变，背景在 Icon Composer 里用纯色 / 渐变重建。
- [ ] 若自导入背景层，已确认 full-bleed 且 opaque。
- [ ] 色彩空间已明确为 sRGB / Gray Gamma 2.2 / Display P3 之一；优先矢量（SVG / PDF）。
- [ ] 能矢量化的主形状已重建为 SVG / PDF；SVG 中的文字已转轮廓，不支持的特性改用 PNG。
- [ ] 已记录目标系统版本，并在 Icon Composer 中**按版本分别检查**（26 与 27 渲染有差异）。
- [ ] 已说明 App Icons 名称必须与 Icon Composer 文件去掉扩展名后的名称一致（**扩展名以当前 Xcode 版本为准，本 Skill 不指定字面**）。
- [ ] 已说明该文件会**替换**原有 `AppIcon` asset catalog；旧系统图标由 Xcode 自动生成，若要保留自定义旧外观需另行保留资产并承担两套维护成本。
- [ ] 已说明最终效果需要在 Icon Composer / Xcode / 实际设备中验证。

⚠️ **未确证**：本次未取得 App Store Connect 对图标素材硬性要求的官方页面（返回 404）；**提交前按 App Store Connect 现场要求核对**像素、位深与 alpha，不要凭记忆写死。

## 10. 交付状态描述

只使用真实完成状态：

- `concept generated`：已生图，尚未小尺寸验收；
- `visual approved`：图像层面通过上述 QA；
- `production handoff prepared`：已有 layer map 和重建说明；
- `Icon Composer verified`：**只有**把资产真正放进 Icon Composer、并且**在目标系统版本上分别检查过**（至少覆盖 26 与 27 的渲染差异）才可以这样写。早于 27 的系统上 Refraction 设置没有可见效果、选择 Inside / Outside 时 specular highlights 常开，属预期行为，不算缺陷；
- `Xcode/device verified`：只有真实运行验证过才可以这样写。

不要把一张 AI PNG 自动描述成“production-ready Apple icon”。
